# PC-1.5 Live Producer Pilot Runbook

Release candidate: CoverageFit 3.20.51  
Readiness profile: PC-1.5

## Before the session

1. Deploy this complete package to the intended pilot environment.
2. Open the Agent Workspace on Dylan's intended Safari/macOS device.
3. Connect the secure producer inbox and synchronize a server-backed pilot consultation.
4. Select that consultation and wait for the preflight's secure save/recovery check to pass.
5. Open the Consultation Document from the preflight. Follow the PC-1.4 Print setup guide, inspect every page in Print Preview, and test Save as PDF and the intended physical printer.
6. Return to the same open Workspace and confirm the device preview check. Begin only when the preflight says Ready for pilot.

## During the session

- Follow the existing Command Center and Current Focus guidance.
- Use the existing Understand, Verify, Discuss, Recommend, Decide, and Next step sequence.
- Treat homeowner-reported, inferred, missing, and needs-confirmation information according to its existing evidence state.
- Do not use checklist completion as verification or a professional recommendation.
- Record producer judgments only in Recommendation Builder and the outcome only in Consultation Completion.

## Recovery check

After recording non-sensitive working progress, refresh or reopen the selected consultation on the pilot device. Confirm that the preflight returns to secure-save readiness and the existing checklist restores the newest valid checkpoint. The device Print Preview confirmation must reset after a page reload; recheck the document before continuing.

## Closeout check

1. Save recommendation judgments and Consultation Completion through their existing controls.
2. Open the Consultation Document again and confirm that its homeowner story, priority order, recorded decisions, unresolved items, and next step match the Workspace.
3. Repeat Print Preview and physical output review if the consultation content changed.
4. Record any product defect outside the homeowner consultation record. Do not put access keys or unnecessary personal information into defect evidence.

## Evidence required for PC-1.6

- deployed environment and build version;
- Safari and macOS versions;
- physical printer or PDF destination used;
- pass/fail for secure inbox sync and cross-refresh checklist recovery;
- pass/fail for recommendation and completion persistence;
- pass/fail for document consistency, page review, Save as PDF, and physical output;
- accessibility or usability observations from the producer;
- defect list, severity, disposition, and retest result.

The preflight means the software path is ready to be exercised. It does not itself prove that a live pilot occurred, that every device will print identically, or that an insurance, carrier, coverage, rate, eligibility, or underwriting outcome exists.
