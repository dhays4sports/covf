# RC-SMS-1.5 — Secure Personalized CoverageFit Continuation

## Status
Implemented and verified in CoverageFit 3.20.23.

## Objective
Connect a completed homebuyer SMS intake to the existing CoverageFit Home journey without asking the buyer to repeat the property and purchase details already supplied by text.

## User flow
1. The buyer completes the RC-SMS-1.4 property address, closing date, occupancy, and auto-review questions.
2. CoverageFit creates a random 128-bit handoff token after the conversation reaches `coveragefit_ready`.
3. The final SMS includes a `https://coveragefit.com/sms/continue/?token=...` continuation link.
4. The continuation page resolves the token server-side, removes the token from the visible URL, stores the verified intake in the existing CoverageFit personalization profile, and routes through the existing transition experience.
5. CoverageFit Home receives the property address, homebuyer review reason, closing context, occupancy, auto-review interest, and RUSH priority without those values appearing in the URL.

## Privacy and security
- Public links contain only a random opaque token.
- The D1 record key stores a SHA-256 hash of the token rather than the raw token.
- Property address, closing date, occupancy, and bundle interest remain server-side until the same-origin handoff resolver retrieves them.
- The public API response excludes the RingCentral phone number and internal conversation identifier.
- Tokens expire after 24 hours.
- Invalid, missing, or expired tokens fall back to the generic CoverageFit Home review.
- The continuation route is `noindex,nofollow` and removes the token from browser history before navigating onward.

## Zero-repeat payload
The handoff carries:
- review reason: Buying a home
- property address
- closing date and display timing
- occupancy
- auto-review interest
- standard or RUSH priority
- bounded source/campaign metadata

No quote, eligibility result, coverage determination, or underwriting promise is generated by this handoff.
